## Verified evidence (judge reproduced it)

| ID | Verdict | Finding |
|---|---|---|
| C1 | Partly | θ was never calibrated against a real R distribution. A single 20/20 interest at the rarity floor gives R = 0.650, which clears ring 3 (0.62), so one-interest profiles can game the gate. Four identical interests at rarity 0.5 give R = 0.777, below θ_far 0.86. A domain-only 20/20 at high rarity gives 0.417 and clears ring 2. (The critic's "one shared interest = 0.636" case actually had three identical interests.) |

## Prioritised backlog (judge)

**P0, before any real member or seeded data**
1. Column-level profile update grants. `is_test` and engine fields move to tables members can't write.
2. Replace the open directory with `get_candidates(ids[])` and `search_members(q, limit ≤ 20)` SECURITY DEFINER RPCs. They exclude blocked pairs, incomplete profiles, and test rows for real viewers.
3. Test-data isolation, plus a one-statement purge.
4. Storage and form limits: bucket size and mime limits, private chat attachments with signed URLs, and a rate limit or captcha on careers.
5. Request spam limits: note length, a daily cap per sender, and expiry.
6. The like flow (Ruling P13), already being fixed.

**P1, next iteration**
- Onboarding: taxonomy, passion points, city picker, server-snapped coarse cell, and a k-anonymity floor.
- ORBIT service trust-boundary design: a dedicated DB role, JWKS JWT verification, safe-card projection last, and rate limits.
- Gate calibration, with an R-distribution golden test and a breadth penalty.
- Sybil hardening: likes weighted by trust, caps, likes counted only if seen, and a floor on load from likes alone.
- A neutral prior when `about` is missing.
- Rarity shrinkage toward a global prior.
- Deck basics: remember seen cards, an end-of-deck state, and empty states that say why and offer an action.

**P2, later**
- Impression and interaction logging with propensities, plus calibration. The *schema* is pulled into iteration 2.
- Explainable cards: stop showing the exact city now.
- Accessibility polish.
- Server-side daily limits, and Worth-the-Distance capped per day.
- IP hygiene: provenance headers and private tuned config.
- CI and the engine-tables migration.
